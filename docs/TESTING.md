# Verification strategy

## Commands and boundaries

| Command | What it actually verifies |
|---|---|
| `npm run lint` | App, tests, scripts and config; excludes installed Python dependencies, model cache and generated reports. No application security/lint rule is disabled. |
| `npm run typecheck` | Next route type generation and full TypeScript checking. |
| `npm test` | Vitest API, Unicode rendering, save/error states, recommendations, contracts, UTC streak and SM-2 tests. Database tests execute all SQL migrations in local PGlite PostgreSQL with Supabase-style auth roles. |
| `npm run test:nlp` | Real spaCy tokenization/POS/lemmas/NER; grammar and correct-text regressions, vocabulary, filler detection, Unicode, alignments/WER, bounded FastAPI/auth/schema tests, mocked model/provider failures. Install the trained English model first. |
| `npm run evaluate:nlp` | Reproducible development-set measurements in `nlp-service/evaluation/results.json`. Export `NLP_ENABLE_EMBEDDINGS=true` and install/download optional models for real semantic results. |
| `npm run test:e2e` | Chromium against actual Next.js pages. Auth provider and external/API responses are test fixtures. Tests interact with sign-in, central cycle, feedback, selected phrases, reviews, history, progress, writing, shadowing, error recovery and mobile navigation. |
| `npm run test:integration` | Actual private FastAPI HTTP server with real spaCy/MiniLM → Next route → real local PostgreSQL analyses, practice, flashcard, review and stats. Supabase authentication and client transport are substituted with a local SQL adapter. Not a hosted Supabase/OAuth test. Requires model files and permission to bind localhost. |
| `npm run build` | Actual optimized Next.js production compilation and route generation, with bundled fonts. No remote font fetching. |

`tests/fixtures/*-analysis.json` were generated by the actual local Python pipeline from original example text. They are response fixtures, not fabricated learner records. Tests don't call paid APIs and don't add an authentication bypass to application code. The test auth HTTP server lives only under `tests/e2e`, binds to loopback, and is launched only by Playwright. Production code always authenticates with Supabase.

## Database cases

Local SQL tests cover atomic session/chunk/reward save, duplicate completion, repeated same-day attempts, rollback, preserving/deduplicating legacy phrases, SM-2 rescheduling/review deduplication, rejecting browser XP writes, cross-user analysis ownership, original/rewrite persistence, quotas and explicit analysis deletion. The HTTP integration additionally checks actual computed NLP output reaches storage and that review updates stats from 25 to 35 XP with two daily activity completions.

PGlite is PostgreSQL in WASM, not Supabase's full hosted platform. Auth schema/roles are local shims. Hosted grant defaults, deployment connectivity, OAuth redirects, email delivery and operational migration behavior require staging verification.

## Manual staging acceptance

After reviewing/applying migrations to a non-production Supabase project, configure real credentials and verify:

1. Request an email link and complete the callback; verify Google separately if enabled.
2. Complete the cycle with microphone input; inspect browser/provider permission behavior, non-English accents, silence and network interruptions.
3. Check that the transcript analysis and completion appear under the signed-in user; repeat Save to confirm no duplicate rewards.
4. Save and review phrases, return tomorrow, and check rescheduling/streak behavior across UTC midnight.
5. Save first/final writing drafts; confirm individual edits preserve intended meaning.
6. Play ElevenLabs audio and replay a local recording; inspect lexical alignment and ensure no acoustic score appears.
7. Sign in as another user and confirm private records cannot be read or referenced.
8. Test model-service/provider outages and daily quota errors; verify texts remain recoverable.
9. Review privacy notices and choose an operational retention policy before onboarding real learners.

Do not run tests against production, print real transcripts to logs, or substitute a privileged service key to make RLS checks pass.
